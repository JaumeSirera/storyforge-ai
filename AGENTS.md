- Public sector pages use a shared browser-safe SectorLanding with independent leaf routes and metadata; why: each audience needs a shareable URL while demonstrations and navigation stay consistent.
- The landing demonstration uses local story data and client-only scoring without creating candidate sessions; why: visitors must try it without accounts or external database access. Demo videos (tour, launch, sector and assistant clips) and their posters are static files under `public/demo/` referenced by root-relative path, never platform asset pointers; why: those URLs only resolve on the platform host and 404 on the user's own hosting.
- Self-hosting build: `npm run build:web` (script = `vite build --config vite.config.hosting.ts`) run outside the Lovable sandbox (unset LOVABLE_SANDBOX/DEV_SERVER__PROJECT_PATH) produces a node-server `.output/` for the cPanel Node.js app; why: Lovable sandbox forces the cloudflare preset. User-facing steps live in `DEPLOY.md`.
- Paid features (donations, subscription, pricing) are hidden behind `DONATIONS_ENABLED` in `src/lib/features.ts`, never deleted; why: the project is free/open source for now but may re-enable them.
- Collaborator program lives in the PHP API (`api-php/src/Contrib.php`, `/api/v1/contrib/*`, tables auto-created) and grants role `collaborator` in `app_user_roles` only on admin approval; why: Lovable Cloud is paused and all data lives in the user's MySQL.
- Despliegue manual: se compila con vite.config.hosting.ts, se empaqueta `.output/` (server + public + nitro.json) en un ZIP y el usuario lo sube a xandralyze-web; no hay integración con GitHub Actions. Por qué: el usuario decidió seguir apañándose con el ZIP de siempre.
- Estudio de redes sociales (ex Story Weaver Social) vive bajo /app/admin/social, datos en la API PHP (`api-php/src/Social.php`, `/api/v1/social/*`, solo rol admin); LinkedIn se publica con el conector LinkedIn de Lovable (`src/lib/linkedin.server.ts`) y el hosting propio, sin esa conexión, reenvía a `/api/public/social/linkedin-relay` de la app publicada en Lovable con firma HMAC de EXTERNAL_API_TOKEN; el resto de redes va por Upload-Post (clave y perfil en `app_social_settings`, `publishCredentials()`); cron de cPanel llama a `/api/public/social/publish-due` con SOCIAL_CRON_SECRET. Por qué: el usuario quiere LinkedIn con su conexión original, independiente de Upload-Post.
- Social publish acknowledgements are stored as `enviando` with per-platform request tracking in the existing result field; only confirmed platform outcomes count as published, and manual checks/cron poll existing jobs without re-uploading. Why: Upload-Post can accept a job before Facebook or other networks publish it.
- SEO guides are data entries in `src/lib/guides.ts` rendered by `GuideArticle` with HowTo/Article/Breadcrumb JSON-LD from `guideHead`; each guide still needs its own leaf route file and a sitemap/llms.txt entry. Why: consistent structured data and shareable URLs per guide.
- Simulation practice runs are marked with `candidate_fields_data.__practice` (no new column) and excluded from evaluator lists/comparisons; why: the external MySQL schema is not migrated automatically.
- Recordings rotate the camera MediaRecorder every few minutes and upload each standalone part while recording (whole-file uploads, no resumable protocol); why: the PHP file API only accepts complete files and a dropped connection must not lose the whole session.
- The in-app assistant (mounted in the `_authenticated` layout) shows stacked colour-over-mask media from `public/assistant/` through a WebGL canvas: a calm, seamless idle loop always underneath, the greeting video crossfaded on top, and while speaking the shader warps the live idle frame's own mouth (lower lip drops a few px and the upper lip lifts about half as much, the gap covers the original lip seam so no dotted shadow shows, soft dark interior with a faint teeth hint; shape constants in `src/lib/assistant-lipsync.ts`) by the smoothed loudness of the reply audio; never paste mouth images over the face, a static patch over a moving frame leaves shadows and size mismatches; replies are voiced sentence by sentence (`src/lib/assistant-speech.ts`) with the next part prefetched so speech starts quickly; never swap whole talking frames, the head would jump. Reply voice and dictation fallback use the user's own OpenAI/ElevenLabs keys (`assistant-voice.functions.ts`), falling back to browser speech; app-help answers come from local data in `src/lib/assistant-help.ts`, free questions go to `askAssistant`. Why: no paid real-time avatar or Lovable service, transparent media that also works in Safari/iPhone, and it runs on the user's own hosting.
